# Fix: matrix enchant stats not applying on equip (mod-random-enchants)

## What changed and why it matters

Equipping an item carrying a scaled matrix enchant (IDs 100000–102624 in the
`spellitemenchantment_dbc` mirror) showed the enchant name in the tooltip but
raised **no stat** on the character sheet. The roll and the quality-variant
system worked; only stat application was dead.

**Root cause** (verified against this fork's core, the vanilla DBC, and the
live DB): the matrix rows encoded `Effect_1 = 6`. In this fork's
`ItemEnchantmentType` enum (src/server/shared/DataStores/DBCEnums.h:368-374)
and in the 3.3.5a client, `ITEM_ENCHANTMENT_TYPE_STAT = 5`, `RESISTANCE = 4`,
and `6` is `ITEM_ENCHANTMENT_TYPE_TOTEM`. The server's stat application path
(`Player::ApplyEnchantment`, src/server/game/Entities/Player/PlayerStorage.cpp)
only enters the STAT case for type 5; the TOTEM case does nothing for armor and
non-shaman weapons. So every equip cycle visited the PROP slot, read the
enchant, and dropped out with no modifier applied. The tooltip still showed
"Scaled Intellect" because the row exists and `Name_Lang_enUS` is populated —
the row was merely the wrong effect type.

**Fix (direction a — smallest, module-side, vanilla-consistent)**: correct the
row encoding to `Effect_1 = 5` (STAT). The other fields were already right for
both server and client: `spellid[s]` maps to EffectArg (the ITEM_MOD, e.g. 5 =
Intellect), `amount[s]` maps to EffectPointsMin, and real vanilla stat enchants
("+1..5 Intellect", IDs 79-95) use exactly type=5, arg=ITEM_MOD, min=max=amount.
No C++ changes, no conf changes, no rebuild, no git operations.

## Files that carry the change

- **`modules/mod-random-enchants/tools/generate_enchant_matrix.py`** — the
  generator now defines `STAT_EFFECT_TYPE = 5` (named constant near the other
  embedded constants), its docstring retracts the earlier wrong "6 = STAT"
  claim (6 is TOTEM, 4 is RESISTANCE), `emit_sql` writes
  `str(STAT_EFFECT_TYPE), "0", "0"` for Effect_1..3 with a corrected comment,
  and `main()`'s sanity block asserts `STAT_EFFECT_TYPE == 5` so a wrong
  constant fails loudly. Everything else (ID formula, STATS/ITEM_MOD table,
  BANDS, TIER_MULTIPLIERS, rung ladder, sanity checks) is unchanged.
- **`modules/mod-random-enchants/data/sql/db-world/002_mod_re_enchant_matrix.sql`**
  — regenerated by the generator (pure stdlib, idempotent `REPLACE INTO`).
  All 2,625 rows now carry `Effect_1 = 5`; zero rows carry 6. EffectPointsMin
  = EffectPointsMax = amount, EffectArg = ITEM_MOD, names, and all gate
  columns (Condition/RequiredSkill/RequiredLevel = 0) are identical to before.
- **Live DB `spellitemenchantment_dbc`** — re-applied with the regenerated SQL
  (REPLACE INTO is idempotent and overwrites all 2,625 rows in place), then
  **worldserver restarted** — required because this fork loads the
  spellitemenchantment store once at startup and has no `.reload` command for
  it. Verified live: `SELECT COUNT(*), MIN(Effect_1), MAX(Effect_1), SUM(Effect_1<>5)
  FROM spellitemenchantment_dbc WHERE ID BETWEEN 100000 AND 102624` → `2625, 5, 5, 0`.
- **Untouched by design**: `src/random_enchants.cpp`, `src/random_enchants.h`,
  `conf/random_enchants.conf.dist` (module logic was already correct), and all
  of `src/server/game/` (core forbidden by spec). The working tree has zero
  modified tracked files and HEAD is unchanged — `modules/*` is gitignored, so
  this fix lives in the working tree only, per the no-commit requirement.

## How to verify

- **File check**: `grep -cE "^\([0-9]+,0,5," 002_mod_re_enchant_matrix.sql`
  → `2625`; `grep -cE "^\([0-9]+,0,6,"` → `0`.
- **Regenerate** (if ever needed): `python3 tools/generate_enchant_matrix.py`
  from the module directory; the assert in `main()` fails loudly if the
  constant regresses.
- **In-game (manual, operator step — needs a client)**:
  - Existing pre-fix enchanted characters (e.g. items with enchant 100000 in
    PROP slot 7) now show the stat on equip.
  - Deterministic per-stat test — set the enchant on a fresh item and equip:
    INT 100000, SPI 100025, STA 100050, STR 100075, AGI 100100, SP 100125,
    AP 100150, MP5 100175, CRIT 100200, HASTE 100225, HIT 100250, EXP 100275,
    DEF 100300, DODGE 100325, PARRY 100350 (band-1/tier-1/rung-0, amount 10;
    ratings appear as rating values, MP5 in the mana-regen tooltip).
  - Unequip removes the stat; re-equip applies it exactly once (no double);
    a relog while equipped keeps it applied — all driven by the same core
    STAT path with apply=true/false.
- **Regression**: the enchant roll, quality/variant system, and enchant-count
  chain are untouched (`random_enchants.cpp` unchanged; `pickEnchant` still
  validates rows via `sSpellItemEnchantmentStore.LookupEntry`).
