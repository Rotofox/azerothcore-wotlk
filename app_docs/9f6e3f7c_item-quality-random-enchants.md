# Item Quality + Scaled Random-Enchant System — `modules/mod-random-enchants`

## Summary

The module was reworked from the old enchant-only behavior into the full
"Item Quality + Scaled Random-Enchant System" specified in
`specs/db8e1683_item-quality-random-enchants.md` (status: implemented; the
build plan is `specs/9f6e3f7c_random-enchants-build.md`). On every awarded item
(loot pickup, profession/create, quest reward, group-roll reward) the award
flow now runs **two independent rolls**:

1. **Quality roll → visible variant swap (or STAY).** A weighted roll over
   `{ STAY } ∪ availableTiers` from a per-(ilvl band, base quality) rates row
   picks a quality tier T1–T5 or the explicit STAY outcome. On a tier, the
   item is swapped to a real `item_template` variant row of that tier (scaled
   stats, own quality color and prefixed name). On STAY, the item keeps its
   base quality and the enchant roll still runs on the base item. Loot tables
   are never modified — the swap happens in the module at award time.
2. **Scaled random enchants.** The existing chained roll (70 % → 65 % → 60 %,
   no total cap) is re-sourced from an ilvl-scaled `spellitemenchantment_dbc`
   mirror matrix and moved from enchant slots `{0, 1, 5}` to the **PROP slots
   7/8/9**, so random enchants no longer collide with the TEMP slot used by
   rogue poisons / shaman weapon buffs.

This matters because it turns a flat random-enchant addon into a loot-quality
system: items can visibly upgrade quality with scaled stats, high-end legendary
rolls are deliberately rare (rates tuned per band), and enchants scale with the
base item's ilvl band.

## Files that carry the change

All work lives in `modules/mod-random-enchants/` (uncommitted working tree; the
module is a nested git repo — see the note at the end).

**Reworked code**

- `src/random_enchants.h` — adds `QualityTier`, `Archetype`, `WeaponPool`
  enums, `EnchantRollResult`, and declarations for the new free functions
  (`rollQualityAndEnchant`, `getIlvlBand`, `rollQualityTier`,
  `getVariantEntry`, `swapToVariant`, `getArchetype`, `getStatPool`,
  `getMatrixEnchantId`, `pickEnchant`, `rollOneEnchant`); adds an include
  guard and moves `AddRandomEnchantsScripts` from an inline definition to a
  declaration.
- `src/random_enchants.cpp` — `rollQualityAndEnchant` replaces
  `rollPossibleEnchant` as the entry point called by the four PlayerScript
  hooks (`OnPlayerLootItem`, `OnPlayerCreateItem`,
  `OnPlayerQuestRewardItem`, `OnPlayerGroupRollRewardItem`). The award flow
  implements spec §1.5: guards (config-gated, class filter, re-roll protection
  via `mod_re_item_variants`), capture of the BASE template before any swap,
  quality roll (STAY returns `std::nullopt`), variant lookup + swap
  (`SetEntry` / `SetState(ITEM_CHANGED)`), chained enchant roll on PROP slots
  7/8/9, then the unchanged "Newly Acquired … N random enchantments!" chat
  message. `swapToVariant` additionally clears stale instance random-property
  state (`ITEM_FIELD_RANDOM_PROPERTIES_ID`, `ITEM_FIELD_PROPERTY_SEED`, PROP
  slots 7–11) when the base template carried a `RandomProperty`/`RandomSuffix`
  (e.g. entries 727, 862), so nothing fights the matrix enchants on slots 7–9.
  `RollLegacyEnchants` keeps the old pool path for
  `RandomEnchants.UseLegacyEnchantPool = 1` rollback mode.
- `src/RE_loader.cpp` — **unchanged** (plain loader stub).

**Config**

- `conf/random_enchants.conf.dist` — 11 new Quality System keys per spec §4.8:
  `QualitySystem.Enable`, `QualityRatesTable`, `PoolRatesTable`,
  `ClassArchetypeTable`, `VariantMappingTable`, `VariantEntryBase` (1000000),
  `EnchantMatrixIdBase` (100000), `EnchantMatrixRungs` (5),
  `StatlessSeed.Enable`, `UseLegacyEnchantPool` (0), `VariantPrefixes`
  (Superior,Exquisite,Regal,Legendary,Mythic). Existing options unchanged.

**SQL (data/sql/db-world/)**

- `001_mod_re_rates.sql` — hand-written seed data: `mod_re_rates` (28 rows,
  (band, base_quality) keyed per spec §4.3, weights relative), 
  `mod_re_pool_rates` (56 rows, armor/weapon/jewelry/relic pool weights per
  §4.4), `mod_re_class_archetype` (10 rows per §4.5). Idempotent
  (`CREATE TABLE IF NOT EXISTS` / `REPLACE INTO`).
- `002_mod_re_enchant_matrix.sql` — generated by
  `tools/generate_enchant_matrix.py`: 2625 `spellitemenchantment_dbc` rows
  (band × stat × tier × rung, IDs 100000–102624) with the §3.0 DBC gate
  recorded in the header (max live enchant ID 3883 < 100000). Single-effect
  STAT enchants; magnitude = `round(rungValue × tierMultiplier)`.
- `003_mod_re_variants.sql` — generated by `tools/generate_variants.py`: 81
  `item_template` variant rows (entry ≥ 1000000, from 23 seed base items) plus
  81 `mod_re_item_variants` mappings. Every variant row has
  `RandomProperty = 0` and `RandomSuffix = 0` (free PROP slots).
- `item_enchatment_random_tiers.sql` — **kept untouched** (legacy pool, used
  only in `UseLegacyEnchantPool = 1` mode).

**Tools and docs**

- `tools/generate_enchant_matrix.py` — pure Python 3 stdlib matrix generator;
  deterministic and idempotent (`REPLACE INTO`).
- `tools/generate_variants.py` — pure Python 3 stdlib variant generator;
  deterministic seed run by default, `--seed-entries` / `--all` modes; forces
  and asserts `RandomProperty`/`RandomSuffix = 0` on every row.
- `README.md` — what changed, regeneration commands, the client DBC patch
  requirement (documented only, not built), v1 notes (locale rows out of
  scope, loot-window base-name nuance, read-per-roll rates).

## How to use / verify

1. Apply the three SQL files to the world DB (they are idempotent, safe for
   the core SQL updater).
2. Config defaults match spec §4.8. Set `RandomEnchants.UseLegacyEnchantPool =
   1` to restore the old enchant-only behavior.
3. Runtime check: loot a low-level white item → bag shows a prefixed variant
   name/color on an upgrade, 1–3 enchants land on PROP slots 7–9, and rogue
   poison / shaman imbue (TEMP slot) still works on the same weapon. Most
   drops STAY (no swap) and still receive enchants; epic bases only upgrade to
   legendary; legendary bases never swap.
4. Tuning: rates are read per roll — `UPDATE mod_re_rates` (quality weights
   incl. STAY) and `UPDATE mod_re_pool_rates` (pool weights) take effect on the
   next roll.
5. Regenerate the SQL:
   `python3 tools/generate_enchant_matrix.py` and
   `python3 tools/generate_variants.py [--seed-entries … | --all]`.
