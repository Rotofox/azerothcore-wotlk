# Root-cause evidence (verified in this repo — verify further, don't take on faith)

- The module applies enchants via `item->SetEnchantment(PROP_ENCHANTMENT_SLOT_0..2, matrixId, 0, 0)` + `player->ApplyEnchantment(item, slot, true)` at award time (random_enchants.cpp). At award time the item is NOT equipped, so `Player::ApplyEnchantment` returns early on `!item->IsEquipped()` — the enchant is persisted (item_instance shows it) but no stat applies then.
- On equip, the core calls `Player::ApplyEnchantment(Item* item, bool apply)` (src/server/game/Entities/Player/PlayerStorage.cpp:4291), which loops EVERY slot 0..MAX_ENCHANTMENT_SLOT (so PROP slots ARE visited) and per slot reads `enchant_id`, looks up `sSpellItemEnchantmentStore`, then for each of MAX_ITEM_ENCHANTMENT_EFFECTS effects: `enchant_display_type = pEnchant->type[s]; enchant_amount = pEnchant->amount[s]; enchant_spell_id = pEnchant->spellid[s]`.

Then it switches on `enchant_spell_id` as the ITEM_MOD (case ITEM_MOD_MANA/HEALTH/AGILITY/STRENGTH/INTELLECT/SPIRIT/STAMINA/... -> HandleStatModifier + ApplyStatBuffMod / rating mods).
